## First-time local setup

<Prompt description="Copy — end-to-end dev environment" actions={["copy", "cursor"]}>
Help me run NextBase Starter locally from a clean clone on [macOS/Linux/Windows].

Follow AGENTS.md and docs getting-started:
- pnpm install at repo root
- Copy .env.local.example and .env.development.local.example only if missing
- pnpm database#start, wait for Supabase ready, pnpm supabase:sync-env
- pnpm dev or pnpm web#dev

Context7 query-docs for Supabase CLI start and Docker requirements if errors mention containers.
When something fails, ask for the exact command output before guessing.
</Prompt>

## Sync env after Supabase restart

<Prompt description="Copy — keys out of date" actions={["copy", "cursor"]}>

Verify:
1. pnpm supabase:sync-env from repo root (not apps/web only).
2. Root .env.local has URL and anon key matching local CLI output.
3. Context7 query-docs for Supabase local API URL and service role vs anon usage in Next.js.

List which env vars NextBase reads (NEXT_PUBLIC_* and server-only) without printing secret values.
</Prompt>

## Deploy to Vercel with Supabase

<Prompt description="Copy — production checklist" actions={["copy", "cursor"]}>
Deploy NextBase Starter to Vercel using hosted Supabase project [REF OR DESCRIPTION].

Checklist with Context7 query-docs for Vercel Next.js env vars and Supabase redirect URLs:
- NEXT_PUBLIC_SUPABASE_URL, NEXT_PUBLIC_SUPABASE_ANON_KEY, NEXT_PUBLIC_SITE_URL
- Supabase Auth URL configuration for production domain and /auth/callback
- No service role key in NEXT_PUBLIC_* 
- Run pnpm build locally first; note Cache Components or middleware edge constraints if any

Output ordered steps for Dashboard + Vercel UI, not generic advice.
</Prompt>
