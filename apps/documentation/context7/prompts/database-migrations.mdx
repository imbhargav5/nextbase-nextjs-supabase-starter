## New table with RLS

<Prompt description="Copy — add a table users can only access their rows on" actions={["copy", "cursor"]}>
Add a Postgres table `[TABLE_NAME]` with columns: [LIST COLUMNS AND TYPES].

NextBase workflow (mandatory):
1. Edit apps/database/supabase/schemas/*.sql — do NOT hand-write migrations.
2. Context7 query-docs for Supabase RLS policies using auth.uid() and FOR ALL / SELECT / INSERT patterns.
3. Enable RLS; policies must match how apps/web uses src/data/user/ (user_id or owner column).
4. From apps/database run: supabase db diff -f [migration_name]; review SQL; pnpm gen-types-local from repo root.

Add a pgTAP test under apps/database/supabase/tests/ if similar tests exist for other tables.
</Prompt>

## Fix RLS permission denied

<Prompt description="Copy — user cannot read/write expected rows" actions={["copy", "cursor"]}>
Authenticated user gets permission denied on [TABLE/OPERATION]: [ERROR OR SYMPTOM].

Investigate:
1. JWT role and auth.uid() in policies vs column values in the row.
2. Whether the app uses anon key with user session (expected) vs service role (avoid in web app).
3. Context7 query-docs for Supabase RLS debugging and policy examples.
4. Compare with docs/SUPABASE_GETCLAIMS_AUTHENTICATION.md for claim/SSR issues.

Suggest policy SQL fix in schemas/*.sql and migration steps — no direct edits to old migration files.
</Prompt>

## Generate and review a migration

<Prompt description="Copy — walk through db diff review" actions={["copy", "cursor"]}>
I edited apps/database/supabase/schemas/[FILE].sql. Generate the migration and tell me what to verify.

Run or instruct: cd apps/database && supabase db diff -f [name].
Review generated migration for:
- Unexpected drops or data loss
- RLS enablement on new tables
- Index on foreign keys used in queries

Context7 query-docs for anything unfamiliar in generated SQL.
Then: apply locally, pnpm gen-types-local, and list apps/web files that need type updates.
</Prompt>
