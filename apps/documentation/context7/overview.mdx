Context7 gives Cursor **current documentation** for libraries and frameworks instead of stale training data. NextBase docs pair Context7 with **copy-ready prompts** so you can ship features faster with fewer hallucinated APIs.

## When to use Context7

Use Context7 when you need accurate, version-aware answers about:

- Next.js App Router, Cache Components, and Server Actions
- Supabase Auth, SSR clients, RLS, and migrations
- shadcn/ui, Tailwind CSS v4, Zod, and `next-safe-action`
- Playwright, Vitest, and Turborepo scripts in this monorepo

Skip Context7 for pure refactors inside this repo when you only need local code search.

## Enable Context7 in Cursor

1. Open **Cursor Settings → MCP** (or install the Context7 plugin from the marketplace).
2. Add the Context7 server if it is not already listed.
3. Confirm tools such as `resolve-library-id` and `query-docs` appear in the MCP panel.

<Tip>
  The repo root includes a Cursor rule that tells agents to prefer Context7 for library and API questions. Keep that rule enabled when working on NextBase.
</Tip>

## How agents should fetch docs

Agents should resolve a library ID, then query docs for **one concept at a time**:

1. `resolve-library-id` with the library name and your goal.
2. Pick the best match (official package, high benchmark score, version-specific ID when you care about a release).
3. `query-docs` with the library ID and a specific question (auth, caching, migrations—not everything in one call).

<Prompt description="Copy — teach Cursor to use Context7 on this stack" actions={["copy", "cursor"]}>
